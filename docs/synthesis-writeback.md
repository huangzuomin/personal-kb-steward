# Synthesis Writeback v1

研究问题 → 当前资料检索 → Claim/Evidence 综合 → 差异提案 → 原审核流程 → 更新主题页。
不是把旧 LLM 预览或聊天原文直接复制入库，也不新造一套写入器。

## 使用

```bash
python scripts/kb_index.py rebuild
python scripts/synthesize.py "大黄鱼 渠道机会" --topic "大黄鱼产业"
python scripts/synthesize.py "大黄鱼 渠道机会" --topic "大黄鱼产业" --discussion "重点比较品牌与销售渠道的关系，这只是待核对的想法"
```

`--topic` 必填，是稳定的目的主题，研究问题可以变化。已有页按精确标题匹配，
歧义时使用 `--target` 指定对象 ID 或知识库相对路径。模型不能指定路径或身份。
`--limit` 默认 8，限制新检索来源数量；已有主题的来源仍保留，不能因未命中而遗失。
问题最多 2000 字符、单行；讨论要点最多 12000 字符。不自动读取任何聊天历史。

命令展示检索诊断、决定、计划位置、审核项和逐行差异。不接受 `--apply`。
用 `personal_kb_steward.py review show/approve/apply-approved` 查看并审核已有队列。
conflict 只留下原因与不可执行的提案，批准冲突项也不能生成页面；noop 不写计划或队列。

## 输入与写回

复用 Retriever 的 FTS/实时补查；用主题名和研究问题找资料，来源正文取当前 Markdown。
目标本身不作为自己的证据。未命中的已有来源同样检查版本和依赖诊断。
没有缓存时按既有规则显式回退文件扫描，不自动建库。查询不是语义检索，必要时用空格分隔关键词。

只调用一次综合模型，不先生成自由摘要再二次转码。实际模型返回的每条判断必须通过
Reconcile 的逐字引文/定位验证。仅在讨论里出现的内容无法作为引文依据。
讨论可引导研究，但不是事实或来源；片段存在不代表语义上足以支持判断，仍须人工审核。
已知 stale 或 conflict 的来源先处理上游，不把过时判断作为新综合的依据。
无版本、未核对的来源仍可生成待审核提案，但诊断完整保留在模型上下文和计划中。

更新只替换原 Reconcile 资料综合区块及其拥有的元数据，保留手写正文、自定义字段和
BOM/换行格式。问题与讨论要点记录在 `reconcile_state.synthesis_request`，与提案一致。
ID/revision、source_hashes、Claim/Evidence、processed index、run/attempt 仍用原实现。
不追加会随重复运行不断增长的诊断段落，不给原始资料添加字段，不改变旧 `task --use-llm` 的预览语义。

同一问题、讨论、来源版本和综合区块未变化时，无模型调用、无新版本。
新问题/讨论即使复用相同来源也可形成新判断；若模型返回完全相同的判断和证据，仍 noop。
此时不为单纯记录新问题而增版，未落盘的问题再次运行可能再次调用模型。
普通 `reconcile.py --source` 保留原先按来源版本判断 noop 的行为。

检索到模型读取之间的版本变化不能偷偷重绑；保存、重存和应用时继续检查来源与目标。
成功或部分写入后被拒绝的重试不能覆盖原执行记录。包含 update 的自动回滚仍保守拒绝；
纯 create 回滚不等于元数据也完成了跨文件事务恢复。

## 边界

完整输入（已有页、旧/新来源、问题、讨论和诊断）受 `reconcile.max_context_chars` 约束，
默认 60000；超限要求缩小范围或先提炼来源笔记，不静默截断证据。该限制是字符数，不是 token 数。
问题、讨论、已有页及选中资料会发送给用户配置的模型提供方；本地检索不额外调用模型。
没有跨文件事务、新数据库、后台任务、自动认可事实或真实模型质量保证。
依赖诊断受索引覆盖及扫描时间限制；不持续监控所有未选中的祖先。完成更新后显式 rebuild，
即可检索新判断、查询 Evidence，并继续使用 impact/stale。
