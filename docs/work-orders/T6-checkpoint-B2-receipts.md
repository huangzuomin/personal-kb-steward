## Root decisions after B2 design review

Read `docs/iteration-evidence/M3-integration/B2-design-note.md` for current seam analysis, with these corrections taking precedence:

- Store versioned receipts in saved plans, bind target catalog AFTER `bind_plan_objects`, persist through the existing save call. Match exact saved-plan hash plus execution evidence for completed outputs. Processed-index is a convenience lookup, never sole write proof.
- Hash actual local generator/prompt/schema/template implementation bytes; constants alone cannot detect an edited prompt whose version constant was not incremented. Exclude credentials and runtime/run/time/path noise. Do not use function reprs. A small explicit transitive file inventory is acceptable only if complete and checked.
- Self-output exclusion must cover the verified output cohort of the prior saved plan, not only the same producer's card. Concept/case/topic generated together otherwise invalidate one another immediately after apply. Exclude only exact recorded path/identity/revision/hash matches while testing the candidate prior receipt; preserve every genuinely new external dependency. Test immediate init and finalize repeats, not only a second repeat that happens to stabilize.
- Keep intake per-original completion separate from cumulative derived discovery. A complete concept/case/topic evaluation of originals A+B must not reuse A-only receipt; yet a read but uncited original is not automatically an error requiring endless regeneration. Record it as evaluated for that stage under its complete, explicitly validated producer result. Citation membership is evidence use, not the entire generation-input closure. For source/seed, preserve explicit validated per-input completion and required-target sets; partial coverage or missing disposition never becomes zero by inference.
- Fix B1b updater disposition first: generated candidate success followed by blocked update must remain blocked for final input processing. A confirmed same-identity noop can reference verified existing output; it is not a fabricated new page or an error.
- No new force/retry command in B2. Rejected exact receipts remain visible without automatic resubmission; changed true inputs can produce a new proposal. Preserve failed execution history and existing application guards.

Root actual derived-repeat BEFORE is now recorded: `astra-B1b-derived-repeat.json` and `astra-B1b-repeat-diff.json`, probes under `.execution/astra-B1b-derived-repeat.py` and `astra-B1b-repeat-diff.py`. A real applied nine-page public vault yields 3 new calls and 3 update proposals on unchanged inputs. All three semantic/generated digests are identical; only related-context hashes changed. New concept/case/topic outputs replace the two original seed-related candidates and even introduce self hashes. Preserve this evidence. Exclude verified own/cohort outputs BEFORE bounded retrieval selection, not after top-k (otherwise the prior seed context disappears and fingerprints still differ). Reuse request-scoped Retriever and its scoped-index option rather than a second ranking algorithm. Excluding a self target from generation context is distinct from preserving its base hash for safe update preflight. Do not cure this by dropping hashes for context actually supplied.
