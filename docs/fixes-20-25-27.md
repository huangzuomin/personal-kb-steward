# 渲染、信号与审核执行修复（#27 / #25 / #20）

本次只修已核实的执行问题。不重构 seed 定位、不自动补 related、不合并 PR #28、不迁移旧库、不自动批准质量问题。

## #27：生成成功必须包括完整渲染

Jinja2 缺失时抛出 `RendererDependencyError`，在 source 编译调用模型前检查依赖。不再返回只有 frontmatter、标题和 summary 的残缺页面。渲染异常不再被当成模型异常转为启发式成功；需要的模板上下文缺失仍由 StrictUndefined 报错。

使用当前解释器安装依赖：

```sh
python -m pip install -r requirements.txt
```

source-note 单来源是合法的；它不是多来源专题结论。干净 LLM 提取结果使用 `growing / compiled / medium`，compiled 在这里仅表示本次来源提取完成，不表示事实被独立证实。存在 quality_flags、摘要/事实缺项，或非 LLM 模式时使用 `manual_review / needs_context / low`。计划层不再按 sources 目录位置抹掉审核状态。运行日志保留计划审核提示，已批准提示不重新计入 processed-state 的未解决问题，避免已审核输入循环处理。启发式和未知分析模式的 apply 门禁读取结构化 analysis_mode，同时兼容旧正文标记。

新增测试替换了旧测试中把启发式来源页当作 high/growing 的断言。未统一其他 skill 的全部 JSON schema。未提供旧残缺页自动修补；安装依赖也不会自动重跑 processed-index 内的旧资料。

## #25：摘录过滤与敏感内容边界

普通围栏早已过滤，本次不是补一个不存在的普通围栏功能。现在保存围栏字符和长度，异种、过短或带信息字符串的围栏不能作为闭合；未闭合围栏保守跳过余下文本。引用和列表包装作保守处理；这不是完整 CommonMark 解析器。

裸命令、配置、独立代码片段、机器串、裸地址和纯引用不进入 seed 信号。正常短句、技术说明和夹有行内代码的自然语言保留。`signal_sentences()` 保留原 API；`signal_excerpts()` 提供实际选中行的 `body_line`，它是传入 body 的行号，不是剥离 frontmatter 前的全文行号。摘录仍不等于已验证的断言。

`content_safety` 检查明确凭据赋值、常见 token 形态、私钥标记、Bearer 和孤立混合机器串。共享 LLM 请求入口在联网前检查内容，在返回模型内容前再检查；source 编译在清洗/截断前检查原输入。敏感阻断不能被聚类或 source 的启发式 fallback 吞掉。计划保存和 apply preflight 再检查派生内容；异常不包含命中值。认证配置/header 不作为待扫描笔记内容。

规则是保守 tripwire，不是完备 DLP，不证明任意文本可以公开。公开 IP、域名本身不标为凭据；可疑机器串也不等同已确认密码。占位符和环境变量引用可以保留。遇到误拦请本地复核并移出不应外发的内容，不要修改审核状态绕过。未删除、改写、轮换任何真实资料或凭据；旧卡回填另立审核计划。

## #20：明确本轮，明确每个 run 的结果

推荐流程：

```sh
python scripts/personal_kb_steward.py init-kb --batch-size 3
python scripts/personal_kb_steward.py review list --run-id RUN_ID --all
python scripts/personal_kb_steward.py review show ITEM_ID
python scripts/personal_kb_steward.py review approve ITEM_ID --reason "已核对来源与质量标记"
python scripts/personal_kb_steward.py review apply-approved --run-id RUN_ID
```

`--run-id` 使用完整 ID，不支持前缀匹配。选择计划后还要在 apply 读取时核对其 run_id。暂停和审核应用使用同一个阻塞判据，列出每条 ID、类型、状态；pending/rejected/未知状态都阻塞，不仅限于页面审核类型。损坏队列在应用前拒绝读取，不静默丢掉损坏的潜在阻塞项。

无范围参数时，为兼容旧单轮脚本，只在唯一已批准 run 时执行；多个 run 时拒绝写入。需要全局执行必须明确使用：

```sh
python scripts/personal_kb_steward.py review apply-approved --all
```

每个成功 run 立即保存审核完成状态。后续 run 失败不抹掉先前完成事实；失败后停止继续写入，汇总 applied/blocked/failed/already_applied/not_attempted。待应用计划不等于已写页面数，页面数以原 apply 的输出与 manifest 为准。含 pending 的 run 不自动放行。`review list` 和显式 `batch-approve` 可用 --run-id 限定范围；未新增按质量类型预授权。

这不是多文件事务、并发 writer 锁或自动恢复器。执行中审核项变化会拒绝覆盖审核记录，已发生的写入依靠 run manifest 排查。部分写入、已执行 run 和包含 update 的回滚限制保留，禁止盲目重放。#18 的宿主删除守卫与 #19 的原生 Windows 路径问题不在本次改动内。
