## 可以交给工作区 Agent 的任务

查看这个主题每条判断的证据。检查哪些上游资料变了。把新的研究问题形成更新提案。

Agent 必须先确认 Steward 仓库路径及其 config.json 指向的知识库，不能把仓库根目录当成 Vault。
命令在 Steward 仓库执行，不在本页目录执行。查询命令不调用模型；synthesize 会向已配置模型发送选中的资料。

```text
python scripts/claims.py <主题页的知识库相对路径或对象ID>
python scripts/workspace_report.py
python scripts/synthesize.py <研究关键词> --topic <稳定专题名> --target <对象ID或路径>
```

更新提案仍走 review show → 用户确认具体提案 → review approve → review apply-approved。
不要在 Base 里手改 object_id、revision 或审核字段来替代批准，也不要用 CLI append/overwrite 直接改受管主题页。

> [!important] 三种状态分开看
> status 是知识生命周期，stage 是工作阶段。页面 review_required 是持久标记，不等于当前审批队列。
> 表格用公式展示，减少误改属性；这不是权限隔离，Obsidian 本身仍允许编辑原文件。
> 没有过时提示不等于结论正确；复查快照不自动刷新，也不自动把 status 改成 stale。
